# HUTOJ Hydro 比赛客户端插件

适配并在本地实际运行验证：Hydro **5.0.4**、ui-default **4.58.4**、Node.js 24。插件源码使用 TypeScript，发布包包含已编译的 CommonJS 入口，可由 Hydro 直接加载。安装到 Hydro 的服务端插件，与 Electron 客户端分别发布。

## 本版提供

- 0.7.1 网页屏幕监控在选手姓名下显示客户端上报的系统和局域网 IP，随页面现有刷新更新；旧会话缺少信息时显示“—”。不向普通参赛授权开放设备信息。

- 比赛编辑页的“允许客户端”和“仅允许比赛客户端”随“更新”按钮保存。两项都关闭时仅网页可参赛。勾选“允许客户端”时网页和客户端均可参赛。勾选“仅允许比赛客户端”会同时启用客户端，并要求选手通过客户端进入题目和提交。升级后，原先勾选“使用比赛客户端”的赛事按“允许客户端”处理。
- 按 Hydro 已有学号、实名姓名匹配账号，使用只限当前比赛的客户端授权；直接将实名设为域内 `displayName`，无需再次填写姓名。
- 0.7.0 客户端登录时统一返回所有有权访问的比赛域中已报名且未结束的客户端赛事，包括未开始的比赛；保留账号固定比赛域、域权限及赛事分组限制。确认后原子锁定目标域与比赛，查看卡片、环境检测和赛前详情不会启动个人计时。旧客户端继续使用原来的单域协议。
- 比赛中每 5 秒检测应用和 AI 插件，先弹窗提示，持续 60 秒未处理则锁定红色全屏警告；该倒计时不展示。管理员可在网页屏幕监控页解除当前选手的全屏警告。
- 设备关联的客户端会话、15 秒心跳、90 秒租约、同一账号同一比赛的并发设备检查。
- 保护原生题目列表、题目查看／提交／附件和评测记录入口。正在受限比赛中的选手不能省略 `tid` 转为普通题目入口。
- 原生提前结束、恢复比赛；以 Hydro 个人状态决定是否可解锁，不依据客户端倒计时。
- 启用客户端即要求网络管控与屏幕监控都就绪；采集分辨率由客户端显示器决定，比赛设置保留帧率、码率和网络放行主机。WHIP 地址模板、媒体管理 API 地址和录像回放服务地址在控制面板的“系统设置 → 比赛客户端”统一配置，对所有域和比赛生效。

服务端插件本身不提供 Windows 防火墙服务、WebRTC 媒体网关或录像服务。Electron 桌面端已通过本插件协议接入真实比赛，并实现 Windows 防火墙及 WHIP 推流；浏览器演示仍使用独立模拟数据。`networkControlled` 和 `screenCapturing` 是客户端报告，不是服务端对隔离或录像成功的证明。启用比赛客户端限制后，两项环境条件都必须就绪。

## 安装（由服务器管理员执行）

下面是服务器管理员的安装步骤。远程部署需单独获得授权，并在替换插件和配置前保留备份。

1. 在开发机运行 `pnpm pack:plugin`，得到 `release/hutoj-contest-client-plugin-0.10.2.tar.gz`。
2. 将安装包传到服务器并解压，注册本地插件目录。例如以当前 root 管理的 Hydro 为例：

   ```bash
   mkdir -p /root/.hydro/addons
   tar -xzf hutoj-contest-client-plugin-0.10.2.tar.gz -C /root/.hydro/addons
   hydrooj addon add /root/.hydro/addons/hutoj-contest-client
   ```

   包含已编译的 `index.js`、模板和 TypeScript 源文件，不需要在插件目录运行 npm install。Hydro 由宿主提供。

3. 在 Hydro 的管理配置页面 `/manage/config` 中，将下面内容合并到现有 YAML（保留其他现有配置）：

   ```yaml
   '@hutoj/contest-client':
     clientKey: '替换成至少32字符的随机部署密钥'
   ```

   可用 `openssl rand -hex 32` 生成密钥。也可通过 Hydro 进程环境变量 `HUTOJ_CONTEST_CLIENT_KEY` 提供，它优先于上述配置。密钥与客户端部署配置一致；不要放入前端页面、UiContext 或代码仓库。这是受管机房的接入凭据，不是硬件认证。

4. 按现有 PM2 管理方式重启 **Hydro 进程**，然后打开一场比赛的 `/contest/<比赛ID>/client` 检查插件设置页。安装初次需要重启；比赛配置保存立即生效。

设置页权限与原生比赛编辑一致：有全域编辑比赛权限，或比赛所有者具有编辑自己比赛权限。关闭“允许客户端”会同时取消“仅允许比赛客户端”。保存后，在线客户端下一次获取状态收到 `released`。

## 创建测试比赛

1. 用普通参赛账号测试；拥有比赛管理权限的账号可绕过限制以便管理。
2. 在 Hydro 创建比赛、添加可正常评测的题目，并通过比赛用户管理加入测试选手。客户端不自动报名。
3. 在比赛编辑页勾选“仅允许比赛客户端”，点击“更新”。客户端须完成该赛事配置的环境检测和屏幕监控才能 ready。
4. 使用 Electron 客户端按 [API.md](API.md) 登录、建立客户端会话、填写显示名并完成网络管控、屏幕监控和 ready，然后进入原生题目列表、提交。
5. 检查未携带客户端会话时无法查看比赛题目／提交；提前结束后 `unlockAllowed=true`；管理员恢复参赛后必须重新 ready。

非默认域使用 `/d/<域ID>/...`；客户端应使用接口返回的 URL，不能硬编码默认域路径。域绑定域名时 Hydro 也会按域配置生成地址。

## 监控参数

在控制面板的“系统设置 → 比赛客户端”配置三个媒体地址，与录像存储目录同组。对应 YAML：

```yaml
contestClient:
  whipUrlTemplate: 'http://media.example:8889/{domainId}/{contestId}/{uid}/{sessionId}/whip'
  mediaApiUrl: 'http://127.0.0.1:9997'
  mediaPlaybackUrl: 'http://127.0.0.1:9996'
```

系统设置保存后立即全局生效，比赛设置不能覆盖这三个地址。有效策略版本同时包含比赛配置和全局媒体地址；地址变更后原有就绪状态失效，客户端需重新就绪。升级时，每项未配置的全局地址仅在旧比赛的非空值一致时自动迁入；值不同则保留旧数据，管理员需在系统设置中统一配置。显式清空的全局地址不会再次导入。

采集使用客户端主显示器的原始分辨率，不由服务端指定宽高。帧率默认 10 fps，目标码率默认 2000 kbps。服务端只下发参数，客户端向配置的 WHIP 地址推流。

WHIP 模板示例：

```text
http://media.example:8889/{domainId}/{contestId}/{uid}/{sessionId}/whip
```

支持 `{domainId}`、`{contestId}`、`{uid}`、`{sessionId}`；会话重建产生新的 sessionId，避免不同选手和重连互相覆盖媒体流。将域、比赛和 UID 保留在流路径中，便于后续录像平台对应选手。媒体服务鉴权、编码兼容、实时观看和服务端全程录像需要在媒体链路阶段实现；这里不返回假造的录像成功状态。

网络放行主机一行一个，接受 IPv4 或主机名，仅放行 TCP 80/443。平台、WHIP 信令及其服务器返回的 ICE 端点自动加入精确放行集合。其他端点用 `networkAllowEndpoints`，如 `tcp://172.31.2.2:2333` 或 `udp://192.168.1.100:8189`，一行一项，支持 IPv6。客户端使用 Windows WFP 按程序、IP、协议和端口过滤；不使用动态 `Internet` 关键字，不放行整个私网，原有安全软件的拒绝规则仍有效。

`processBlackList` 按进程名精确匹配，`keywordBlackList` 匹配进程名和程序描述，`keywordWhiteList` 优先排除误报，均一行一项、忽略大小写。默认列出常见浏览器、通信及远控进程，可由管理员编辑；仅报警，不强杀程序或自动交卷。客户端 5 秒扫描、缓存描述并按进程启动实例去重，随 15 秒心跳上报。管理员从比赛管理侧栏“赛事答疑”下方的“屏幕监控”查看最近 200 条记录，记录时间由服务器生成，内容为“检测到张三运行违规应用‘谷歌浏览器（chrome.exe）’”这类中文句子。客户端不上传完整进程清单、路径、命令行或文件内容。

## 数据与恢复

- `hutoj.client.settings`：每域、每比赛一份策略，保存操作者、更新时间与策略版本。
- `hutoj.client.sessions`：每域、每比赛、每用户一份当前会话。仅存 token SHA-256，存设备 ID、会话 ID、租约、最近客户端报告及最多 200 条进程违规记录。同设备重登录保留记录。比赛结束后至少保留 7 天后由 TTL 清理；不是永久审计档案。
- 同设备重开会话立即轮换 token；其他设备需等原租约过期。管理员可提前结束该选手比赛，再按 Hydro 原生恢复流程处理。
- 网络超时和无效会话都不能视为解锁。有效旧 token 的租约即使过期，仍允许只读查询结束状态；不续租、不允许题目访问或提交。token 被轮换后旧 token 完全失效。
- 取消参赛、删除比赛、数据库错误等返回错误；不会自动给出解锁授权。客户端不保存本机登录信息，异常重启需重新登录；无法恢复时，管理员确认比赛结束后可运行仓库的 `scripts/repair-network.ps1` 删除本机防火墙规则。
- 管理员恢复比赛、策略变化、采集／管控报告失效都会使原 ready 失效。客户端必须重查并重新完成环境准备。

## 开发验证

插件依赖 Hydro 的 `template` 服务，在每次加载时注册自身模板及 DEV 源文件路径，覆盖服务启动后的安装和热更新。仅依赖 Hydro 启动扫描会使新模板缺失，并在读取含公告/答疑的题目列表时返回 HTTP 500；0.3.1 已补充此路径与隔离回归测试。

在仓库根目录：

```bash
pnpm test:plugin
pnpm typecheck:plugin
pnpm test:plugin:hydro
pnpm test:plugin:imported
pnpm start:plugin:local
pnpm stop:plugin:local
pnpm pack:plugin
```

第一组使用真实临时 MongoDB 测试租约原子性、身份绑定、并发、状态机和钩子边界。第二组在隔离的临时 Hydro profile 和数据库中启动真实 Hydro 5.0.4，通过 HTTP 验证原生模板、比赛编辑开关、显示名、题目访问、真实提交记录、提前结束、恢复和跨域 URL。第三组使用本机 `/root/Hydro` 开发源码，将本机数据库的只读快照恢复到独立端口的临时 MongoDB，加载 15 个既有插件及本插件；在副本中启用 onsite-toolkit 的 `contestMode` 并验证姓名限制、题目访问、真实提交和提前结束。2026-11-03 已在 WSL Hydro 5.0.7 上通过 22 项检查。测试使用临时文件存储、关闭副本判题与榜单外发，并清理副本任务队列；不要求原数据库账号有创建其他数据库的权限。提交测试验证创建真实评测记录，不验证判题结果。

测试数据库只监听本机，进程退出后清理；首次运行 mongodb-memory-server 会下载 MongoDB 测试二进制。测试不访问正式 HUTOJ，也不修改现有 Hydro 配置。导入数据库测试从当前配置读取 MongoDB 地址，复制后只写临时副本；会在临时目录保存数据库快照，恢复完成即删除。当前开发版与插件的联调已覆盖本机全部已启用插件；正式服务器环境仍需真实测试比赛验证。

`start:plugin:local` 会保留一个已加载插件的本机隔离实例和数据库副本，地址、测试账号记录在仓库的 `artifacts/local-hydro-test.json`。`stop:plugin:local` 会停止该实例、临时 MongoDB 并删除副本。Windows 上这些命令自动调用 WSL。2333 开发进程已加载 `/root/Hydro/plugins/hutoj-contest-client`；本机 `/root/.hydro/addon.json` 已注册插件，`/root/.hydro/env` 已配置本机部署密钥。此操作不涉及远程 HUTOJ 服务器。
